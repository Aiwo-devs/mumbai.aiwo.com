# Git & Repository Authorship Guardrails

Rules for keeping this repository's history and public-facing text clean and professional.

## Repository naming

Never include names of AI assistants, coding agents, model providers, external design-reference companies, or implementation tools in:

- branch names
- commit messages
- tags
- PR titles
- PR descriptions
- changelog entries
- filenames
- source comments
- TODOs
- generated reports intended for Git
- public documentation

## Commit messages

Commit messages must describe the product/engineering change only.

**Good:**
- `Standardize reusable button variants`
- `Align CTA states across service pages`
- `Add responsive tertiary button treatment`
- `Improve button accessibility states`

**Bad:**
- `Claude updated buttons`
- `AI-generated button redesign`
- `Copied buttons from external reference`
- `Agent implementation`
- `MCP button changes`

Do not attribute commits to an AI assistant. Do not add statements such as `Generated by Claude`, `Co-Authored-By: Claude`, `Co-Authored-By: AI`, `Created with AI`, or `Implemented by an agent`, unless explicitly requested for that commit.

## Git metadata

- Do not alter the configured Git user name/email.
- Do not add AI-related co-author metadata.
- Do not rewrite existing Git history.
- Do not modify existing remote configuration without explicit approval.

## External design references

External references used during development (e.g. a Figma file used purely as a visual/structural reference) must not become product or code terminology. Production code uses AIWO-neutral semantic naming only (e.g. `primary` / `secondary` / `tertiary`, not names tied to the reference source).

## Commit control

- Do not create a commit unless explicitly approved for that change.
- Do not push.
- Do not create a branch unless explicitly requested.
- Do not open a PR.
- Do not modify the Git remote.

All Git write actions require explicit approval, scoped to what was actually requested.
